Shellboy Studio for Windows x64 (unsigned)
See the release notes or candidate handoff for real-device check status.

Extract the entire ZIP first. Keep Shellboy Studio.exe and shellboy.exe
in the same folder. Double-click Shellboy Studio.exe; the desktop launcher
opens your default browser and does not open a console. Follow the browser's
connection setup if prompted, then open a conversation.

Microsoft Defender SmartScreen may warn about this unsigned package.
Check the source of your download. Only if you trust it, choose More info,
then Run anyway if Windows offers it. Do not turn off SmartScreen or bypass
your organization's policy.

Double-click again to reopen the running Studio. Closing the browser tab
doesn't stop Studio: use Exit in Studio to stop its server and any Core it
started. A separately running Core won't be stopped. Studio uses the same
settings and data as Core; don't start another owner for the same data while
Studio is running its bundled Core. Studio automatically retries an unexpected
Core crash with increasing delays capped at the owner-start timeout. A clean exit
or startup failure is not retried; use Restart after correcting a startup problem.
A separately started owner is never adopted, stopped, or automatically restarted.

To use an existing TUI's config and data folder, create a shortcut to
Shellboy Studio.exe and set its Target to, for example:

  "C:\Tools\Shellboy Studio\Shellboy Studio.exe" --config "D:\work\shellboy\config.toml" --data-dir "D:\work\shellboy\data"

The options mean the same as in Core. Relative paths start from the
shortcut's "Start in" folder. If the TUI is running on that data folder,
Studio uses it; otherwise Studio starts its bundled Core with both paths.
Only one Studio runs at a time: if it is already running with a different
data folder, a dialog shows both folders and nothing changes. Use Exit in
the running Studio first.

If Studio cannot open, check the dialog and %APPDATA%\shellboy-studio\studio.log
(or owner.log there for bundled Core diagnostics). Do not share tokens or
private log contents. For development flags such as --no-auth, use the separate
console CLI artifact; double-click always uses authentication.
