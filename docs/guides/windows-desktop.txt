Shellboy Studio for Windows x64 (unsigned)
See the release notes or candidate handoff for real-device check status.

Extract the entire ZIP first. Keep Shellboy Studio.exe and shellboy.exe
in the same folder. Double-click Shellboy Studio.exe; the desktop launcher
opens your default browser and does not open a console. Follow the browser's
connection setup if prompted, then open a conversation.

Microsoft Defender SmartScreen may warn about this unsigned package.
Check the source of your download. Only if you trust it, choose More info,
then Run anyway if Windows offers it. Do not turn off SmartScreen or bypass
your organization's policy.

Double-click again to reopen the running Studio. Closing the browser tab
doesn't stop Studio: use Exit in Studio to stop its server and request normal
shutdown of any Core it started. Studio force-terminates that child only if the
request fails or it does not exit within the grace period. A separately running
Core won't be stopped. Studio uses the same
settings and data as Core; don't start another owner for the same data while
Studio is running its bundled Core. Studio allows one immediate automatic
restart per Studio launch or manual Start after an unexpected Core crash. Readiness does not reset that allowance. If the
restarted Core exits again, before or after becoming ready, Studio stops retrying,
shows the last failure, and waits for you to choose Restart; that manual Start
resets the allowance. A clean exit or an initial startup failure is not retried.
A separately started owner is never adopted, stopped, or automatically restarted.

To use an existing TUI's config and data folder, create a shortcut to
Shellboy Studio.exe and set its Target to, for example:

  "C:\Tools\Shellboy Studio\Shellboy Studio.exe" --config "D:\work\shellboy\config.toml" --data-dir "D:\work\shellboy\data"

The options mean the same as in Core. Relative paths start from the
shortcut's "Start in" folder. If the TUI is running on that data folder,
Studio uses it; otherwise Studio starts its bundled Core with both paths.
Only one Studio runs at a time: if it is already running with a different
data folder, a dialog shows both folders and nothing changes. Use Exit in
the running Studio first.

If Studio cannot open, check the dialog and %APPDATA%\shellboy-studio\studio.log
(or owner.log there for bundled Core diagnostics). Do not share tokens or
private log contents. For development flags such as --no-auth, use the separate
console CLI artifact; double-click always uses authentication.

Company PC
----------

Downloaded ZIP. Verify the download and extract it in full. Mark of the Web
may carry through to the unsigned executables. Only unblock a verified ZIP
if your organization explicitly permits it or IT directs you to; ask IT
about a block on either executable. Do not disable Defender or bypass
SmartScreen or application control.

Data. Keep Core's live data on a local, non-synced disk (normally
%LOCALAPPDATA%\shellboy\data). If necessary, use --data-dir with an approved
local folder, not a mapped or UNC share or a OneDrive sync folder. Studio
settings and logs are separate, under %APPDATA%\shellboy-studio.

VPN and proxy. Being on the VPN or opening Studio in the browser does not
prove Core can reach the model service. Core inherits the launcher
environment, not another terminal's environment or the browser's proxy
settings. Ask IT what outbound HTTPS proxy and certificate settings the
Explorer-launched process needs.

Firewall. The desktop bridge listens only on 127.0.0.1, normally port 8751
(an available port if occupied). It does not need inbound LAN access. If
Windows prompts or the local URL is blocked, check with IT rather than
opening a firewall port.

Open at login. A shortcut in shell:startup does not prove Windows will run
it. Check Settings > Apps > Startup and verify at sign-in; if company policy
blocks registration or launch, open Studio manually.

Updates. Use Quit Studio, not just close the tab, and make sure the
processes you are replacing have stopped. Extract the new ZIP and keep its
two EXEs together; do not swap one executable while the other is running.
Update shortcuts if the folder moves.

Removal. Quit Studio, then remove the extracted folder and the Studio
startup shortcut if present. This leaves Studio settings, its token and
logs, and Core's separate config, credentials and conversation data. Keep
the Core files if another client uses them.
