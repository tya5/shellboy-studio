# Studio agent pointer

Studio writes a short, bounded pointer alongside the bundled agent guide in its data directory. When a connected owner exposes `extra_instructions`, the bridge automatically registers the pointer via the owner's hash-checked `config.set`, preserving other paths and order. This default makes Studio tools discoverable without changing project AGENTS files. A persistent Studio configuration opt-out removes only this pointer and prevents future automatic registration. The settings and Apps pages expose the choice and any owner-reported result. Existing prepared turns are unaffected; the owner reports whether restart is required. Older owners retain the copy instructions. No polling is used; connection changes trigger reconciliation. Failures are surfaced and not silently retried.

Validation: a dedicated Shellboy origin/main owner at 321abcc9, temporary data and a loopback mock provider accepted `config.set` with the pointer, reported `applied_to_running_owner=true` and `restart_required=false`, and included the pointer text in the new Thread's model request. A second isolated run verified bridge auto-registration and the resulting model request. A headless Chrome session verified authenticated opt-out restoration and visible save failure; bridge restart preserved opt-out. These runs used no paid provider or user data.
