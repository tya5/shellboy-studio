# Branches and Threads

Status: implemented (2026-11-07), local only. From Shellboy `v0.10.0`: `thread branches`, `thread fork`, `thread rewind`, `thread archive`, `thread unarchive`, `thread list`. Logic is in `web/ui-core/src/branches.ts`, `org.ts` and `branching.ts`; screens in `web/designs/console/screens/Branches.tsx` and `Threads.tsx`.

## Branches: what is real

`thread.branches` returns the family: `depth`, `state`, `running`, `pruned_originals`, `divergence` (`node_id`, `ordinal`, `parent_continues`, `request`), `divergence_unknown`, `tip`, and `size` (`path_nodes`, `nodes_after_divergence`). Every count on the screen comes from those ordinals; nothing is estimated.

### The screen (#138)

The approved mock is `web/designs/console/mocks/branches.tsx` on `wip/studio-branches-redesign-mock` (`53cf3c7`); patterns and sources are in `branches-redesign-research.md` on that branch. Logic: `web/ui-core/src/branch-lanes.ts` (rows, keys, reads); view: `web/designs/console/screens/Branches.tsx` with the `BranchLanes` component.

- **Header:** one sentence ("Release notes split into 3 lines of work. ..."), then one card per line of work: its colour and name, Running or idle, where it came from ("Split from X after #6", "Started apart from X" for `no_shared_prefix`, "The original line"), its size and the age of its tip, and a **Compare** check.
- **Where did it split?** Each Thread is a vertical lane, top is oldest, depth first from the root; children are ordered by where they leave. A lane shows its first message, each point where a branch leaves it (a diamond, with "X splits off here"), any messages opened with **Show**, and its tip (a ringed point under the lane's name, "This Thread" on the viewed one). The stretches between are runs: "N more messages (#a–#b)" from the ordinals. A child's line starts with a curve at its parent's split row and runs beside the parent's later rows; a `no_shared_prefix` child starts apart and is never joined. Columns are reused once a lane ends; past six open lanes, further lanes share the last column and keep their names. Lane colours are the three chart tokens, always written next to the lane's name.
- **Selected message actions:** a click or tap (never hover) selects a message and opens its actions under it. **New branch from here** takes an optional request and runs on one press (`thread.fork` on that row's lane and node, then `message.send` to the new Thread). **Rewind X to here…** first runs the `dry_run`: the rows that would leave that lane are marked on the graph, and the facts are listed (messages and turns that leave, the new branch that keeps them, shell commands and files that are not undone, branches starting in that part, replies still expected, attachments unselected, the owner's truncation and summary notes). Only the second press, **Rewind X**, rewinds; choosing another message or **Cancel** withdraws the preview. A real result links `branch_thread_id`, the kept part; opening it is the undo. A message chosen from a Conversation link (`#/branches/<thread>/<node>`) that is not a row opens the same actions above the graph.
- **How do they differ?** The two checked lines are compared when they are a parent and child or two children that left one parent at the same node (`anchorCandidate`); other pairs say so. The shared history is stated once ("Both share #1–#6, up to ..."), then each side lists its messages after the split (side by side, stacked on a phone), with **Show more** and **Open in Conversation**. The pair defaults to the viewed Thread and the first line it can be compared with.
- **Phone:** the lanes are a full-width list with 44 px rows (`size-touch`), the line cards follow the graph, a tapped message opens its actions under it, and **Compare** in the bottom bar opens the comparison as its own view with a back button; coming back restores the list's scroll position.

### Reads and no flicker

- Family: on opening the view and when the Thread list changes; one at a time, one trailing. No polling. Paging: 200 per page, up to 4 pages (a family is at most 256 Threads). `cursor_expired` starts over, at most 3 times, then is reported. `family_truncated`, `ancestors_truncated` and `root_parent_unavailable` are shown.
- Row text comes from `history.window` (when advertised), only for rows on screen (one IntersectionObserver): a branch's head is one window at its split node with `after: 1`, a root's head is position 0, a split or tip is that node alone, all with `excerpt_chars: 160`. **Show** on a run reads up to 24 positions after the node before it (`ordinal` + `expect_node_id`), at most 480 opened positions per view. At most 2 reads run at once and 48 wait; a row that leaves the screen before its read starts is dropped from the queue. Excerpts are kept by node ID (at most 2048, oldest first out), so a family re-read never reads or clears them. Without the capability no excerpt is read: split rows show the owner's `divergence.request` and tips `tip.last_request`.
- **Stable rows:** row keys are the lane's Thread ID plus a node ID, or a role (`start`, `tip`) or a run's first position. A re-read with the same facts yields the same rows, so every row element, focus, the selected message, its open actions and the scroll position stay. An appended message changes only the lane's last run and its tip, in place; a new lane is appended. Each row kind has a fixed height (`size-control` + `space-8` per message on a wide frame, `size-touch` on a phone; `size-row-action` for the name and split lines; one-line text with an ellipsis), and lane width is fixed per column, so nothing jumps.
- **Loading** shows only on the first family read and on Show more (the run says "Reading"), following the PageRun rule (#124). A comparison re-read (when either side's tip or size changes) keeps the last shown messages until the new ones arrive.
- A family re-read keeps opened positions when a lane only grew. A shorter path, or a new tip without growth, drops that lane's opened positions so they are read again rather than shown from an older path. A rewind and a longer append coalesced into one re-read cannot be told apart from an append; such an opened row can keep an older excerpt until the view is reopened, and an action on it is refused by the owner if the node left the path.

**Conversation marks:** one family read per Thread opened, again when the list shows its children changed. A point on a node with no row goes on the row before it. A point outside the window read shows nothing. Each message has a quiet `Branch or rewind from here` link to `#/branches/<thread>/<node>`, shown on hover or focus on a wide frame.

## Sidebar Thread actions

The standalone Threads organizer has been removed (#138). The sidebar remains the place to find Threads, select rows for bulk delete and archive/unarchive, and access per-Thread actions. Archive requires a second explicit press; unarchive is one press. Both use the existing owner operations and confirmation/count behavior. Move and single-Thread tag editing live in the row menu; the Move picker retains its preview/confirmation and is capability-gated. Tag editing is capability-gated and writes one Thread ID per request. These actions do not create a separate destination or trigger organizer list reads.
