# Monitor cards and panes

Cards scan many Threads: status, relationships and update age, without conversation excerpts. Tiles monitor a small selection as equal, edge-separated panes. A shared `ui-core` selection applies the state filter, pinned-only filter, title search and stable or recent order to both views; switching views does not reset it. Pins and order use per-browser preferences. Search applies to the loaded Thread list.

## Selection and pins

Pins are persisted Thread IDs, independent of the saved state, query and archive filters. Archive and activity changes never remove pins; absence from a paged list is not proof of deletion. The `All` scope shows matches, pinned IDs first. `Pinned only` ignores state and archive filters, but applies the search query. Both scopes and both presentations use the same selection and controls. The monitor requests the owner list with archives included and filters the loaded rows locally; list pagination remains bounded and explicitly user-driven. Pinned IDs use bounded individual `thread.get` reads, at most four at once and at most 100 IDs, on list changes; only an explicit owner `not_found` removes a pin. Results supplement IDs outside the loaded list. Fields not supplied by `thread.get` remain unknown. The selection model owns this queue and cancels it on leaving Monitor or disposal.

The status filter is multi-select. A row already shown that ceases to match status stays in place, with its current status and an out-of-filter indication, until the user changes any filter or presses Refresh selection. Search and archive changes reset the held set. Stable ordering preserves existing row order when statuses change; pin/unpin is a deliberate reorder. A clear-filters action resets state, search and archive scope, without changing pins or the selected all/pinned scope. The display count is over the loaded list, not an owner-wide total. Selected chips stay visible even if their current count is zero. The toolbar exposes common filters in a responsive popover with removable pills.

A page has at most six panes, arranged in equal rectangular grids with no gaps. A remainder of five is split across pages to avoid an empty grid cell. On phone width the panes are one vertical column; only the outer page scrolls. Each pane has a heading with title, state and pin; a clipped, bottom-aligned chronological conversation; and an activity/status line. Messages and tool groups take one line each, with plain text, not Markdown. The pane never scrolls, and the bottom alignment follows new rows. On old owners only the status line is shown below the heading.

Each visible pane owns its intersection observation and lightweight hint subscription. Leaving view closes it and cancels reads; the reader owns a bounded queue (20 IDs), at most four concurrent reads and the previews, which are discarded on removal or shutdown. A page displays at most six panes. Initial display and change/resync hints request one tail `history.window` (`before=19`, `after=0`, `excerpt_chars=160`), then one `shell.list` page (`limit=20`). There is no polling. A new hint cancels older reads; partial shell facts are indicated, never inferred. Status uses the same state mark and activity labels as Conversation, and includes a running shell's description and saved elapsed start when available.

## Validation

`web/ui-core/test/tiles.test.ts` with a fake transport records 20 `history.window` and 20 `shell.list` calls for 20 visible previews; one hint adds one of each and an offscreen hint adds none. The pane screen further limits a page to six. `npm run check` tests selection, pagination, cancellation and the old-owner path. Screenshots use headless Chrome on macOS with a fake owner at 1440 x 900 and 390 x 844. Emulation is not a phone test. The real owner and provider were not used; `history.window` remains behind `next-shellboy`.

## Monitor toolbar

The monitor toolbar has a title and presentation toggle, saved-selection view tabs (all, pinned, attention), a search/filter/sort row, and removable active-filter pills. Attention selects recovery and awaiting statuses in addition to the saved filters; pinned ignores status and archive filters as before. Counts refer to the loaded list, not a global total. The filter and sort popovers close on Escape or outside press, with focus returned on Escape. On narrow frames sorting moves into the filter popover; the toolbar and pills wrap without horizontal scrolling. A view tab never overwrites the saved filters.

Browser validation: run `npx vite --config designs/console/test/browser/vite.config.mjs --host 127.0.0.1 --port 19330 --strictPort` in `web`, then `node designs/console/test/browser/check.mjs` (set `CHROME_BIN` if needed). The isolated fixture uses no owner. The script checks toolbar and popover overflow at 1280 and 390 CSS pixels, including an active filter; optional `SHOTS_DIR` saves screenshots. Emulation is not a physical phone test.
