# Thread artifacts in Studio (#35)

The Possessions tab shows the Core-ordered artifact list above Attachments. The same panel is used inside the narrow Conversation sheet. Studio reads one bounded prefix per visible Thread; More extends it, and Thread change/resync hints rebuild the prefix from the owner. A drill-in opens a separate paged history observation for that artifact. Browsing earlier versions is read-only; metadata carries no authority to modify Core.

The bridge exposes only `artifact.list` and `artifact.get` to Studio. The authenticated `POST /artifact-content` resolves the exact `(thread_id, artifact_id, version)` through the owner; it never accepts a path, URI, MIME or byte budget from a browser. For preview, the bridge uses the live owner config's `limits.attachment_file_bytes` on each request and fails closed if it is absent. The shared bridge semaphore bounds concurrent requests and remains held while a file body is consumed. Only regular files at local absolute paths or local file URIs and in the image or non-HTML text allowlist are streamed. The response is uncached and not navigable as markup. Browser preview is detail-only; it renders text, safe Markdown or an image, discards it on close, and revokes any image object URL. External HTTP(S) links open in a separate browser tab. Explicit desktop open routes through the launcher for eligible known local file MIME types; unknown scheme/type is copy-only. Attachments retain their previous behavior.
