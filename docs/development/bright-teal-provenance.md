# Accent-following approved logo

This supersedes the fixed Bright Teal color choice in the preserved earlier
commit. Geometry/expression comes from `e0b6271ba6bdeb4b2965ec11a342cd1d1a5c7100`;
only normalized rect/path/ellipse geometry was selected, not its private history.
The branch remains derived from audited public base
`f840a32d81db6ee7a0223519b13fbfbdf2ba9047`. No private-main merge is permitted.

## Three deliberately separate color roles

- In-app logo is inline SVG. Tile/wink use existing `--accent`: console #38bdf8,
  light #0369a1, terminal #4ade80. Face #000810 and existing bright details
  #FEF2D1 are generated by the same tokens.json color mechanism, not a second
  theme switch. Logo follows accent; no fixed brand tile/wink palette remains.
- Browser favicon is an external SVG with internal prefers-color-scheme CSS:
  OS light #0369a1, OS dark #38bdf8. It does NOT follow the app-selected theme.
  ICO fallback and apple-touch/install icons remain fixed light-accent colors.
- Fixed master/optical SVG, PNG and ICO outputs use #0369a1 tile/wink. The prior
  nine-file byte equality is NOT evidence for this new color specification.

`tools/brand/geometry.json` retains the original master/16/32 optical geometry.
`generate.py` recolors it and renders with exactly resvg-py 0.5.0 (already installed;
no install is performed). `python3 tools/brand/generate.py --check` rerenders and
compares all 11 output bytes. ICO holds exact 16/32/48 PNG payloads. This tool has
no queue/task/network. The nine old assets are deliberately changed in color;
shapes, stroke widths, tail and facial expression are preserved.

Production Vite emits the explicit allowlist under existing /assets; PNG, SVG,
ICO and manifest receive correct MIME/no-cache. Index CSP permits same-origin
images/manifest; asset responses do not inherit index style-src restrictions,
so external SVG's internal OS media CSS works. No new bridge route is needed.
The actual embedded-handler HTTP test exercises SVG/ICO/manifest bytes and headers
without launching an owner. Header/index/template and browser icon roles are
validated separately; browser tab-chrome/installed-home-screen visibility still
needs human/native inspection.

## Contrast target and honest failures

`tools/brand/contrast.py` implements WCAG sRGB relative luminance. The engineering
target for recognizable graphical distinctions is 3:1, not the 4.5:1 text rule.
The logo is decorative/noninteractive beside its text name, not a status/control.
Do not claim every logo boundary is 3:1: the required bright outer bubble touches
the required accent tile, and console/terminal fail that target. The palette and
shape requirements make those failures unavoidable without another approved
color/geometry change. Do not silently darken accents, alter the ring or add an
outline to hide this limitation. Independent review must explicitly see it.

| Adjacent pair | Console | Light | Terminal | Target |

| Wink / face | 9.406 | 3.396 | 11.563 | 3 |
| Eye and inner bubble / face | 18.073 | 18.073 | 18.073 | 3 |
| Tile / sidebar panel | 8.317 | 5.934 | 11.362 | 3 |
| Outer bubble / tile | **1.921 FAIL** | 5.322 | **1.563 FAIL** | 3 |

The old face #023239 would give light-accent wink 2.332 (FAIL). Deepening only
face to #000810 improves it to 3.396 (PASS), retaining geometry and the required
bright details. Nominal 3:1 concerns the distinguishable interior, not every
antialiased edge pixel. Production browser computed colors, image pixel samples,
18px native logo screenshots and OS-scheme favicon images supplement this table;
small raster/edge recognizability and tab-chrome appearance are not inferred from
nominal ratios alone. Use current contrast.py JSON for unrounded numbers.
