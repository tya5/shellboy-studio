# CASE Display Bundle

S owns the canonical CASE displayPolicy column, normalization fact preservation,
and workElementDisplay(item). CASE category/icon/tool policies are owned by the classifier, not the display
adapter. The adapter has exactly one projected item input. Its source must
have normalizer-issued WeakMap metadata, exact source association fingerprint,
scoped identity and unchanged receipt identity. Matching node IDs cannot recover
metadata for an arbitrary copy. This qualifies same-projection display facts only:
it creates no current-ref, Core, text-body or future freshness authority.

Metadata captures only original node kind/time, actual explicitly associated
execution command/state/exit, or exact public live state/terminal presence. Shell
associations are capped at 64; missing/over-bound metadata denies display facts.
No global lookup, raw item/content parser or extra read. Public reasoning markers
have no approved body and therefore show unavailable content with no expansion.
Core299 uninstalled fields are not consulted. Spill contributes only its published
local identity; original execution lookup is forbidden.

Five exported properties are structured content/context and provenance-bearing
state plus CASE icon, accessible type label and detail policy. Accessible label is
also the same hover title, never a visible type prefix. 6057 owns a pure DS formatter
preserving the source/context reference, exact reason, provenance and exit code;
D must use the qualified projected item and existing detail adapters. No JSX kind
classification, body joins, fake summary, inferred retry or invisible type fallback.

A tool with approved associated shell metadata may use the EXISTING shell-output
adapter; none/unavailable never offers a false expansion. No generic actual-safe-
typed body is emitted in this checkpoint. Unknown and notification rows explicitly
say missing content; timestamps provide honest context, not a cause or summary.
Actual wire/client state stays distinct. Generic live records remain unknown.

## Supported Transient Activity (2026-11-13 Amendment)

The adopted narrow amendment to the conversation Section 2/3 matrix adds
`liveActivity`: Work / Notifications, state-change rendering, inbox icon, no tool
membership or interruption, closed by default, no invented detail body. Only the
live normalizer issues it for public Core v0.13.0 RunState `live`/`stopping` or
TurnState `preparing`/`running`/`waiting` (protocol.rs RunState/TurnState, snake_case).
`recovery_wait`, failures, terminal states, invalid kind/state combinations and
future states retain the visible unknown/Problems path. Saved records named run
or turn are unchanged. Scoped record identity and raw wire state are preserved.
The dedicated display policy consumes that CASE; unknown-problem has no activity
wording exception. No JSX reclassification or hidden records.

The bounded Work query still selects starting/running/stopping/accepted/held;
this amendment does not widen fetching or infer status from page absence. The
actual-App Run fixture injects the public native live state, not a claim that
this unchanged query normally returns it. Turn running is query-reachable.
Removal from a later active page is not proof of successful completion.
Saved body authority, terminal live-off and receipt limits are unchanged.

Tests include every displayPolicy plus scope/copy/receipt negatives and existing
CASE regressions. Initial missing test API names and fixture types are preserved
as author artifacts, not product-red evidence. Normalizer clone metadata omission
was caught during development and corrected; full consumer/UI usage remains a
separate gate. An unused adapter or passing DTO tests do not prove user-visible
completion. No UI files, services, installed Core or user data are changed here.

## Exact Execution And Scoped Work API

workExecutionDisplay(item, executionId) selects ONLY that same item's issued shell
association. Different executions retain distinct safe command/description/state/
exit; missing membership is undefined. Aggregate display must not be copied onto
each execution. Description is the existing public execution field, not raw args.

scopeIssuedWorkFacts(items,keyScope) validates ALL sources before issuing ANY clone.
Only issued unscoped live/receipt facts can gain UI keyScope; saved unscoped facts,
foreign nonempty scope, empty scope and arbitrary copy all fail closed. Existing
same-scoped sources retain identity. Array and new scope are frozen. Receipt scope
is opaque authority and never parsed/rebound as UI keyScope. Fingerprints preserve
source/execution/receipt associations across the module-owned transformation.

D must scope ONLY issued live records/receipt facts. Already-scoped saved sources
and projectOwnedHandoffFacts text/body retain their existing original source path;
they must not be fed through this Work-only issuer. If scoping returns undefined,
retain the previous coherent projection (including independent saved content): no
spread fallback, fabricated display or dropping saved rows. No new read/current
reference authority is conferred. Spill unavailable facts use the existing CASE
and normalizer-issued metadata, without original-node hydration.
