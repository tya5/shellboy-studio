# CASE Display Bundle

S owns the canonical CASE displayPolicy column, normalization fact preservation,
and workElementDisplay(item). Existing CASE category/icon/tool policies are not
reclassified. The adapter has exactly one projected item input. Its source must
have normalizer-issued WeakMap metadata, exact source association fingerprint,
scoped identity and unchanged receipt identity. Matching node IDs cannot recover
metadata for an arbitrary copy. This qualifies same-projection display facts only:
it creates no current-ref, Core, text-body or future freshness authority.

Metadata captures only original node kind/time, actual explicitly associated
execution command/state/exit, or exact public live state/terminal presence. Shell
associations are capped at 64; missing/over-bound metadata denies display facts.
No global lookup, raw item/content parser or extra read. Public reasoning markers
have no approved body and therefore show unavailable content with no expansion.
Core299 uninstalled fields are not consulted. Spill contributes only its published
local identity; original execution lookup is forbidden.

Five exported properties are structured content/context and provenance-bearing
state plus CASE icon, accessible type label and detail policy. Accessible label is
also the same hover title, never a visible type prefix. 6057 owns a pure DS formatter
preserving the source/context reference, exact reason, provenance and exit code;
D must use the qualified projected item and existing detail adapters. No JSX kind
classification, body joins, fake summary, inferred retry or invisible type fallback.

A tool with approved associated shell metadata may use the EXISTING shell-output
adapter; none/unavailable never offers a false expansion. No generic actual-safe-
typed body is emitted in this checkpoint. Unknown and notification rows explicitly
say missing content; timestamps provide honest context, not a cause or summary.
Actual wire/client state stays distinct. Current generic live record CASE remains
unknown: this adapter does not reclassify it from a kind string.

Tests include every displayPolicy plus scope/copy/receipt negatives and existing
CASE regressions. Initial missing test API names and fixture types are preserved
as author artifacts, not product-red evidence. Normalizer clone metadata omission
was caught during development and corrected; full consumer/UI usage remains a
separate gate. An unused adapter or passing DTO tests do not prove user-visible
completion. No UI files, services, installed Core or user data are changed here.
