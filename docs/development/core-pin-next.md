# Core main preparation (Studio #152 / #151)

Core `c10e660485fcf2886597a2aaab107667f55ff937`, protocol 42 (`docs/reference/protocol.schema.json` `$id` `protocol-v42`). This is a Core main snapshot, not a published tag. Cargo.toml and Cargo.lock pin this exact commit. Studio v0.4.4 remains pinned separately; this stacked branch prepares the next pin and is not a release.

| Core change | Studio adoption |
| --- | --- |
| #437, protocol 42 | Running `shell.list` items and `shell.get` results carry typed `foreground` (true only for the execution the current Turn waits on). The shell page decoder accepts a Boolean or null and rejects other values; the UI does not use it yet (Studio #167). |
| #423 Unit 4, protocol 41 | Fresh sends and asks no longer accept `deliver: "now"` (schema `NewDelivery` is `next` or `complete`); an ordinary send never releases a foreground wait. Studio never sends `now`: the browser allowlist admits only `next` sends, and the app host refuses an app `thread.send` with `now` as `invalid_args` before any owner call. Revisit `complete` stays available to apps. |
| #431, protocol 41 | `run.get` may report `stop_settlement_failure` (`storage` or `invariant`) while the same Run is still `stopping`. When the open Thread's work page has a stopping Run, the existing work read issues one `run.get` for it (a Thread has at most one current Run) and shows one supporting line under the conversation status with the Run ID and the pinned recovery guide's steps (address the cause; if that Run is still `stopping`, stop it again). The line appears and clears on the owner's ordinary changed hint. The line is information only: it has no action, and Studio never stops or retries on its own. Run-stop eligibility belongs to Core; the person uses the existing Activity stop, with its confirmation, after checking. Only the typed values are shown; an absent, null or unknown value, or a Run no longer `stopping`, shows nothing. No stop replay and no inference about external effects. |
| #434 (no wire change) | History reads now project the saved sender on named Ask nodes. The named Ask is an `assistant` node on the asking Thread's selected path whose `provenance.sender` is the asking model (`kind: model`, `thread_id`, label). Studio's existing sender decode shows the asking Thread and its self-asserted label, so Studio #163 needs no Studio change; witnessed by a real-owner `history.window` read through the bridge and a mounted timeline test with the same node shape. |
| #159 (not in this pin) | `held_by` is published only by `message.get`; the reply-duty rows behind pending own messages do not carry it. The pending-row line waits for Core #311 4e's selected-window observation (decision on Studio #159). |
| #421 Unit 2, protocol 39 | Register and decode `operation.get` as `OperationReceiptDetails`; require the typed identity/state/uncertainty/replay/targets fields and preserve `outcome` as opaque JSON plus optional downstream evidence; accept the schema's null for absent optional downstream facts. This is observation only: never automatically replay a mutation or infer absence of effects from pending, expired, or missing evidence. No operation-evidence UI in this pin. |
| #423 Units 1-3, protocols 37-38 | `message.get` reports typed `held_by` (exact `foreground_shell.execution_id`), Core `wait` adds exact `message_delivered`, and `shell.background` targets an execution ID. The pinned crate types and real-owner witnesses cover them; Studio's UI does not read `message.get`. Studio keeps Background on the exact reported ID; browser Ask remains denied. |
| #311 4a-out, protocol 40 | Core `shell.read` accepts `tail`; carry the optional wire argument in the typed args, but Studio does not use tail reads in this change. Explicit Background reports the neutral `shell_backgrounded` reason for person and Thread callers; prior person-specific historical reasons remain readable. |
| #416 Unit 1, protocol 30 | Carry effective `limit` and typed `filters` on consumed record pages, including artifact version history. Keep omission flags distinct from selectors; preserve cursor continuation for empty pages. Branch family limits and shell scan metadata remain separate. Compaction is a capped report with `more`, not cursor pagination. Status uses top-level limit without reflecting cursor or memory; memory remains independent. Do not use the new fingerprint as a cursor or a live observation. |
| #416 Unit 1, count and snippet coverage | Use `awaiting_replies_count_exact`, keep directional lower bounds, and preserve `excerpt_omitted`, `excerpt_truncated`, and `execution_count_exact` independently. No inferred count or coverage. |
| #421 Unit 3, protocol 35 | Record the `message.ask` result schema as `MessageAskResult = MessageAccepted` (same accepted shape as Send); decode Ask results with the existing `MessageAccepted` acceptance decoder, including unassigned and named results. The bridge still denies browser Ask; no new Ask route. |
| #422, protocol 36 | Decode Reply with its own `MessageReplied` rule: required nonempty `message_id` and `reply_to`; optional non-null nested `delivery: MessageAccepted`. Standalone replies omit `delivery`; routed replies record acceptance, not completed delivery. Send/Ask remain on `MessageAccepted`. |
| #420, protocol 31 | The CLI's `message ask --sender-label` uses existing Core wire sender metadata. Studio already displays saved sender labels. The bridge still disallows `message.ask`; no browser sender authority or new write route. |
| #416 Unit 2, protocol 32 | Use `parent_thread_id` for Thread create/set and returned Thread facts, including watch summaries and Branches rows. Preserve empty-string detach. Map reply-list requests to `owed_by_thread_id` and `asked_by_thread_id`; do not rename `pending_replies` fields or item `asked_by`. Studio does not issue filtered `history.list` reads by shell state; Core's pinned typed command and app/bridge passthrough carry the `shell_state` contract. |
| #416 Unit 3, protocol 33 | Use `history.read` and `HistoryReadArgs` without changing request shape. Studio only holds opaque page cursors in the current walk; do not reuse old `history.get` scopes across the pin. |
| Other additions in this Core pin | Explicitly deny Core draft commands, `history.recall`, and `history.received` in the exhaustive bridge allowlist. No new Studio surface. |
| #418 | Compare every admitted lane window to the family row's `selection_revision`, retaining the tip/size and window agreement checks. Reject and reread an inconsistent family when a divergence's `parent_selection_revision` disagrees with the parent row. |

The Studio public app bridge returns the pinned Core record envelopes. Core's public `attachment.list` inspection path still sends a bare page despite the schema; Studio accepts that page and validates typed scope and limit if Core supplies them. No client-synthesized metadata. Grouped usage, fixed service/schedule lists, and status memory do not use record pagination.
