# Studio v0.4.4 pairing

Pairing: Core v0.17.0 (`5a164b37deac681520362a8b93b6ca08a47eb3a9`, protocol 36). Cargo.toml and Cargo.lock pin that exact tag commit. The exact-pair real-owner suite runs against that Core with temporary owner data and loopback mock providers, and its Ask/Reply pairing coverage is exactly two witnesses. Standalone: a person's CLI `message ask --thread` into a mock Thread whose model runs `shellboy message reply` for that exact Ask ID; the Reply's root result has `reply_to` equal to that ID and omits `delivery`. Routed: a mock Thread's model runs `shellboy message ask --to human`, and the person answers that exact Ask ID with the CLI `message reply`; the Reply's root result has a nonempty answer `message_id` and a `delivery` whose `message_id` is that answer and whose `thread_id` is the asking Thread. Thread-to-Thread Replies and held or later delivery states are not exercised by these witnesses. macOS and Linux run both live Reply witnesses. On Windows (GitHub `windows-latest`, Core v0.17.0) both are excluded: `shellboy message ask` and `shellboy message reply` run in Core's model shell produced no stdout, only PowerShell CLIXML progress records on stderr ([tya5/shellboy#440](https://github.com/tya5/shellboy/issues/440)). The live Reply path is therefore unverified on Windows. The protocol-pair test separately checks Ask's `MessageAccepted` registry/schema mapping and both routed and standalone `MessageReplied` shapes, including omitted (not null) delivery for standalone replies. Studio v0.4.4 is still unpublished.

Before upgrading, quit both Studio and Core and back up the entire Core data directory.

## Changes since v0.4.3

The following landed commit subjects are quoted from `git log 87785a6..main` on the current main used for this draft:

- **Core protocol adoption (#152):** “Prepare Studio for Core protocol 33 (#152)”, “Adopt Core protocol 34 Branches path revisions”, and “Keep the new command surface closed and honor empty page cursors”. Studio adopts the newer protocol families for Summary and Branches path revisions, keeps unapproved commands closed, and preserves empty cursors.
- **Branches and saved asks:** “Validate saved ask labels and retry Branches reads on the new family”. Saved ask labels are validated and Branches reads retry using the updated family.
- **Summary parts and record pages:** “Witness Summary parts on the exact Core pair”, “Require pinned record facts and preserve advancing cursors”, “Migrate review fixtures and witness malformed and long record pages”, and “Assert the exact empty parts projection for a small manual Summary”. Against the exact tagged Core pair, the small manual Summary returned an explicit empty parts report; retained nonempty parts were not exercised. Malformed and long record pages preserve safe cursor advancement.
- **Owner hints (#152):** “Replay the full loaded record prefix on owner hints (#152)”. Changes within the loaded record prefix are replayed when the owner reports a change.
- **Stop model (#160):** “Separate model and Run stop controls”, “Capture stop targets and report owner refusals”, and “Keep Activity sections and gate Run stop by detail”. Stop model now interrupts only the Turn. Stopping the Run and its shells requires the separately confirmed Stop everything action in Activity.
- **Shared shell-output actions (#161):** “Unify shell output actions in Activity detail”. Copy, Wrap lines, and Formatted controls are shared between output views; inline output retains its title and execution-details action.
- **Long-open tabs (#144):** “Keep mounted icon VNodes out of the glyph registry (#144)”, “Remove work disclosure toggle handlers on unmount (#144)”, “Keep mounted sidebar controls out of App callback scopes (#144)”, and “Document Console component render lifetimes (#144)”. A long-open tab no longer keeps old conversation renders, settings handlers and DOM nodes after you switch Threads (#144).
- **Panel tabs fit (#164):** “Fit docked panel tabs without scrolling or clipping (#164)”, “Keep adaptive tabs on one row and in the dock only (#164)”, “Measure the icons-only fallback in dock and sheet (#164)”, “Preserve sheet touch targets and compact tab badges (#164)”, “Use the sheet perimeter for all six touch tabs (#164)”, “Allow the Conversation sheet to use the phone viewport (#164)”, and “Measure stable available width for panel tabs (#164)”. Panel tabs no longer scroll sideways or clip. On a phone the section picker is replaced by the **Thread panel** sheet, whose six tabs are touch targets. In both the dock and the sheet, the tabs fit the stable available panel width in one of three modes: all labels; only the selected tab's label, with icons for the others; or icons only, with the selected tab's name shown in the heading (the dock's panel heading, the sheet's title).
- **Panel rows (#165):** “Reserve the full panel row action hit area (#165)” and “Share the panel action hit geometry (#165)”. The Awaiting reply list and other panel rows no longer overflow sideways; long titles truncate, and row actions keep a full touch target.
- **Following a conversation again (#166):** “Retire adopted live rows outside the reattached window (#166)”, “Keep detached retirement consistent through publication and capacity (#166)”, and “Keep preview admission separate from accepted history retirement (#166)”. After you leave a conversation scrolled up and then follow it again, finished answers no longer stay stuck as 作成中.
- **README and screenshot fixture (#162):** “Lead the Studio README with reply duties (#162)”, “Preserve README screenshot bytes on checkout (#162)”, “Document the Studio screenshot fixture and published pairing (#162)”, “Refresh the authenticated README screenshot (#162)”, and “Recapture README image with landed panel behavior (#162)”. The README now leads with reply duties, and its screenshot, recaptured with the landed panel behavior, is documented as synthetic fixture data with reproducible generation guidance.
- **Source archives:** “Keep screenshot tooling note archive-safe”. Development guidance no longer links to a browser README omitted from source archives.

## Known issue / 既知の問題

- On Windows, a model may not receive the output of `shellboy` CLI commands run in its shell with Core v0.17.0. Tracked in [tya5/shellboy#440](https://github.com/tya5/shellboy/issues/440) (regression check in progress).
- Windows では Core v0.17.0 の場合、モデルがシェルで実行した `shellboy` CLI コマンドの出力をモデルが受け取れないことがあります。[tya5/shellboy#440](https://github.com/tya5/shellboy/issues/440) で追跡中です（回帰の確認中）。

## Upgrade

Quit both Studio and Core before upgrading. Back up the entire Core data directory before starting the new Core; its startup may migrate data and an automatic downgrade is not provided.
